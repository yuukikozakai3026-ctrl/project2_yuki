# Kenney素材カタログ—新規プロジェクト引き継ぎパッケージ

このフォルダだけで、Kenney素材カタログ・検索機能・運用ルールを完全に新しいプロジェクトへ引き継げます。元プロジェクトやこのPC固有のファイル位置は参照しません。

## 同梱物

- `Kenney_Asset_Catalog.json`：素材候補、公式URL、検索語、用途、注意点を収録したカタログ
- `search_assets.py`：同じフォルダのカタログを検索するプログラム
- `Codex_Kenney_Asset_Catalog_Instructions.md`：詳細な運用ルール
- `AGENTS_SNIPPET.md`：新規プロジェクトの正式な継続指示へ追記する文章
- `README_引き継ぎ.md`：この引き継ぎ手順

## 引き継ぎ先が決めること

引き継ぎ先のChat/Codexは、現在の環境と新規プロジェクトの構成を確認して、次を決めてください。

- 新規プロジェクトの名前と保存先
- このパッケージの各ファイルをプロジェクト内のどこへ置くか
- 新規ダウンロードした配布物の一時保管場所
- 採用した素材とライセンス記録の保存場所
- Unity等へImportする場合の正式な保存場所

ここに書かれた例や旧プロジェクトの配置を、そのまま正解として固定しないでください。プロジェクトの内容やファイル位置は将来変更される可能性があります。

## 導入手順

1. 新規プロジェクトを確認し、既存の資料・ツール・継続指示の構成を把握する。
2. このフォルダの同梱物一式を、引き継ぎ先が適切だと判断した場所へコピーする。
3. `search_assets.py`と`Kenney_Asset_Catalog.json`は、特別な理由がなければ同じフォルダに置く。別々に置く場合は検索時に`--catalog`で実際のJSONを指定する。
4. `AGENTS_SNIPPET.md`の内容を、引き継ぎ先の正式なプロジェクト指示へ重複なく追記する。既存指示は置き換えない。
5. 実際に採用した配置場所と呼び出し方法だけを、プロジェクト指示とプロジェクト限定メモリへ記録する。
6. 下記の検索確認を行う。

```sh
python3 search_assets.py "机" --kind model3d
python3 search_assets.py "土煙" --kind vfx2d
python3 search_assets.py "足音" --kind audio
python3 search_assets.py "ミニマップ" --kind ui2d
python3 search_assets.py "空"
```

コマンドは検索プログラムを置いたフォルダで実行する例です。実際の配置後は、その環境で有効な呼び出し方へ読み替えてください。

## カタログデータの状態

候補情報、公式URL、検索語、用途、注意点、検証情報は引き継いでいます。一方、旧プロジェクト固有の導入状態は持ち込みません。全アセットの`local`は次の初期状態です。

```json
"local": {
  "status": "unknown",
  "path": null,
  "unity_paths": [],
  "verified_files": []
}
```

以後は、新規プロジェクトで実際に確認した情報だけを更新してください。

## 新規取得・非流用の規則

- 素材が必要になったら、旧プロジェクト、過去の展開フォルダ、過去のZIP、既存の素材保管場所から流用しない。
- 同じ素材がこのPCに存在していても、Kenney公式ページから新規プロジェクト用に改めてダウンロードする。
- 公式URL、取得日、配布物のSHA-256、同梱ライセンス、採用した実ファイル、使用箇所を新規プロジェクト側で記録する。
- 必要な候補だけを取得し、カタログを根拠に一括ダウンロードや一括Importをしない。
- 購入、寄付、有料素材の取得は、ユーザーの明示的な承認なしに行わない。

## 検索から利用まで

1. 用途と形式を決める。
2. 日本語・英語の短い名詞で検索する。
3. 上位3件までの公式URL・用途・注意点を確認する。
4. 0件なら同義語を一度試し、その後はKenney公式サイトに絞って調査する。
5. 採用候補は公式ページと実配布物を確認し、新たにダウンロードする。
6. 必要な実ファイルと依存ファイルだけを導入する。
7. 対象環境で見た目・音・依存関係を確認する。
8. 確認できた結果だけをカタログへ記録する。

依頼範囲に素材導入が含まれる場合、検索結果の提示だけで終了しません。候補比較、新規取得、必要ファイルの導入、動作・表示確認まで行います。

## Codexメモリへ保存する内容

新規プロジェクトの場所と実際の配置が確定した後、そのプロジェクト限定のメモリへ次を保存してください。

- Kenney素材カタログと検索プログラムが利用可能である。
- 素材が必要な作業ではカタログを積極的に使う。
- カタログ全文ではなく、上位候補の公式URL・用途・注意点だけを確認する。
- 導入が依頼範囲なら、検索で止まらず新規ダウンロード・導入・確認まで行う。
- 旧プロジェクトや過去の取得物は流用せず、公式配布元から新規プロジェクト用に毎回新規取得する。
- 実際に採用したカタログ、検索プログラム、ダウンロード保管、Import、ライセンス記録の場所を毎回ユーザーへ確認し直す必要はない。
- 実際に確認した新規プロジェクト側の導入情報だけをカタログへ記録する。

新規プロジェクトの配置が決まる前に、仮の絶対パスをメモリへ保存しないでください。

## 完了条件

- 同梱されたJSON、検索プログラム、詳細指示書が新規プロジェクトへ移されている。
- 配置先は引き継ぎ先がプロジェクト構成に合わせて決めている。
- JSONを読み込めてID重複がなく、上記5検索が成功する。
- 全アセットの`local`が旧プロジェクト固有情報を含まない。
- 正式なプロジェクト指示へ運用ルールが重複なく追記されている。
- プロジェクト限定メモリへ、確定後の場所と運用ルールが保存されている。
- 旧プロジェクトや過去の配布物を素材本体として流用していない。

完了報告では、引き継ぎ先が決めたプロジェクト名、実際の配置場所、検索検証結果、指示の追記先、メモリ保存先だけを簡潔に報告してください。
