# Kenney素材カタログ—Codex利用指示書（新規プロジェクト用）

この指示書は、同梱の`Kenney_Asset_Catalog.json`と`search_assets.py`を、新規プロジェクトで運用するためのものです。元プロジェクトの場所や内容には依存しません。

## 基本方針

- 引き継ぎ先が新規プロジェクトの構成を確認し、同梱物の正式な配置場所を決める。
- プロジェクトが既に使用している継続指示へ、`AGENTS_SNIPPET.md`のルールと実際の配置後の呼び出し方を重複なく追記する。
- 既存指示を上書きせず、カタログ全文を継続指示や会話へ貼り付けない。
- 素材本体は旧プロジェクトや過去のダウンロードから流用せず、必要になるたび公式配布元から新規取得する。

## 検索

`search_assets.py`は、特に指定しなければ同じフォルダの`Kenney_Asset_Catalog.json`を読みます。別の場所へ分けた場合は`--catalog`で実際のJSONを指定してください。

```sh
python3 search_assets.py "机" --kind model3d
python3 search_assets.py "土煙" --kind vfx2d
python3 search_assets.py "足音" --kind audio
python3 search_assets.py "ミニマップ" --kind ui2d
```

`kind`は`model3d`、`vfx2d`、`ui2d`、`audio`、`texture`から選びます。最初は日本語・英語の短い名詞を使い、上位3件までの名前、公式URL、用途、注意点、確認状況だけをモデルへ渡します。

0件なら同義語を一度試し、その後Kenney公式サイトに絞って調査します。カタログにないことを、Kenney全体に存在しないことと混同しません。

## 検索から導入まで

1. 必要物と形式を決める。
2. カタログを検索し、上位候補を比較する。
3. 公式ページのプレビュー、配布内容、ライセンスを確認する。
4. 採用する場合は、旧プロジェクトや既存ファイルを使わず公式配布元から新たにダウンロードする。
5. 新規プロジェクト用の保管場所へ置き、取得日とSHA-256を記録する。
6. 必要な実ファイルと依存ファイルだけを導入する。
7. 対象環境で見た目、音、読みやすさ、依存関係を確認する。
8. 実際に確認できた情報だけを新規プロジェクト側のカタログまたは導入記録へ反映する。

依頼に素材導入が含まれる場合、検索だけで完了としません。新規取得、導入、確認まで進めます。

## カタログフィールドの扱い

- `official_metadata`：公式ページに掲載された分類、タグ、Files数、ライセンス表記。Files数を固有モデル数と解釈しない。
- `keywords_ja` / `keywords_en`：検索補助。個別素材の実収録を保証しない。
- `recommended_uses_ja`：想定用途の提案。付属機能の保証ではない。
- `recommendation`：候補の推奨順と適合確認事項。採用済みの意味ではない。
- `check_before_use_ja`：取得前・採用前に確認する内容。
- `verification`：公式情報など、どこまで確認済みかを示す。
- `local`：新規プロジェクトで確認した導入情報。初期状態は全件`unknown`。

`local.status`は次の意味で使用します。

- `unknown`：新規プロジェクトでは未調査・未取得。
- `not_present`：新規プロジェクト用の確認対象を調べ、未導入と確認済み。
- `downloaded`：公式から新規取得した配布物の実在を確認済み。
- `imported`：必要ファイルを対象環境へ導入し、実際の場所と動作を確認済み。

記録する場合は、相対パス、用途、内容確認結果、`candidate` / `accepted` / `rejected`、見た目や用途の評価を残します。取得できたという理由だけで`accepted`にしません。

## 採用判断

### 3Dモデル

対象ゲームのカメラ、寸法、シルエット、色、材質と並べて確認します。プレイヤーカメラで実際に配置して確認し、形が合わなければ次候補へ移ります。素材のために歩行幅、当たり判定、敵経路、ソケット等を無断で変更しません。

### VFX・UI・音・空

VFXは明暗両方の背景で確認し、発光だけで形をごまかしません。UIは使用言語、文字サイズ、余白、既存配色を優先します。音は実際に試聴し、試聴できない場合は未確認と記録します。2D素材やSkyboxを導入しただけでゲーム機能や地形問題が解決したとは扱いません。

## ダウンロード上の制限

- 現在の依頼に必要な候補だけを取得する。
- 推測したZIP URLや一時リンクを恒久的な取得元にしない。
- 公式素材ページから通常の取得経路を使う。
- 旧プロジェクト、既存の展開物、過去のZIPを使い回さない。
- 購入、寄付、有料素材は、ユーザーの明示的な承認なしに取得しない。
- 配布物のライセンス、取得日、公式URL、SHA-256、採用ファイル、使用箇所を記録する。

## 読み込み量

JSONをプログラムが全件読むことは問題ありませんが、モデルへ渡すのは上位候補の名前、公式URL、用途、注意点、新規プロジェクト側の導入状態だけにします。候補探しのたびにカタログ全文を会話へ貼り付けません。

## 導入確認

「机」「土煙」「足音」「ミニマップ」「空」を検索し、候補とURLが取得できることを確認します。加えてJSONのパース、ID重複、検索補助の参照先も検査します。

以後の報告には必要に応じて、用途、採用パック、公式URL、実ファイル、調整点を短く残します。

各レコードの`source_url`を一次情報として扱い、公式ページと配布物が異なる場合は実際に確認した配布物に基づいて更新します。採用時は各配布物内のライセンスも確認し、記録と一緒に保持します。
