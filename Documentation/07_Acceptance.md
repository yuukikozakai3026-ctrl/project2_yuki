# 実装手順・完成条件・検証

## 1. 実装の順序

1. 既存環境、指示ファイル、対象ビルドを確認する。技術選択と版を記録する。
2. カタログを正式配置し、指定Kenneyパックを新規取得。採用モデルの正規化と依存テクスチャを確認する。
3. 共通の舞台・バット・入力アダプター・スロー・時計・得点板を作る。PCに頭と手の入力を与え、実際の接触でボールを処理できる状態にする。
4. Aを5種類、導入、90秒、結果まで作る。指定モデル・粒子・音を適用する。
5. Bの台と各設備を寸法どおり作り、5種類の対処と期限を実装。最後に種類を順番につなぐ。
6. VR実入力とPC自動デモを同じゲームに接続し、双方のモードを切り替えられるようにする。機器がなくてもVR機能を丸ごと省略しない。
7. 指定デモの時間割・成否・画面を確認し、環境に適した実行物を出力する。出力不可ならソース・再現手順・具体的な不足環境を残す。

仮形状で組む中間段階は認めるが、最終成果物を未装飾のキューブ群や無音の消滅で完成扱いにしない。ゲームルールに手を加えずに済むバグ、材質変換、座標変換は自律的に修正する。

## 2. 最低限の確認

| 確認 | 合格条件 |
| --- | --- |
| A/B独立 | 切替で途中状態を破棄、別ルール/別結果で起動できる |
| 初回導入 | 初見でも形と結果が対応。本人の対象が先、実演は必要時だけ。強制操作説明・テストなし |
| VR手・頭 | 実入力の座標を1:1で反映。スロー中も追従。床/目線補正でリグを拡大しない |
| 速度非依存 | 同じ接触部位に静止・遅い移動・速い移動で触れた時、成否/点/演出が同じ。移動差が原因の接触部位の違いは分けて確認 |
| A帯判定 | 帯内・帯外・境界で20/10/20。小さな先端の点だけを狙う判定にしていない |
| 対象の同時性 | 通常は一つだけ。B弾群だけ複数。解決済みの破片に判定なし |
| スロー | 手/時計に影響せず、B弾群は一発目で残りが加速しない |
| ケーキ | 広い皿底で受けられる。縁で即失敗しない。捕捉後に回転しても破壊なし。4秒受取/全工程8秒でリセットなし |
| 爆弾 | 速度で勢いが変わらず、静止接触で連続加速しない。実穴へ落ちる。自動で穴へ向かう力なし |
| 箱 | 静止バットに箱が往復しても1打。15cm退避・再接触を3回行って初めて開く |
| 時計0 | 発射済みは固有期限まで、未発射は中止。時刻0と発射が同フレームなら時計終了判定を先にして発射しない |
| 期限と成功の同時刻 | 接触/落下の連続計算で期限以下の時刻なら成功を先に確定、期限より後なら失敗。フレーム順で変わらない |
| 失敗の回復 | 強制再試行・長いブザー・減点なし。爆弾失敗の片付けは1秒で次へ |
| 打ち返し経路 | 球/弾/花火が発射機と得点板に重ならず、球は遠方網、弾は金属板へ実際に接触 |
| 見た目 | 指定モデルと原寸、画像依存、UI日本語、背景との判別、視界を覆わない粒子 |
| 体格・利き手 | H=1.35/1.65/1.90、右/左で台と接触点が同じdy。文字は読める向き。規定の動作は前方で完結 |
| 自動デモ | 成功は実接触の結果。Aの見逃し、Bの部分弾群・当て直し・期限切れと復帰が出る |

数値処理の検証は得点・時計・再接触・デモとVRの共通経路を重点に行う。見た目の各定数をそのまま写しただけのテストを大量に作らない。

## 3. デモの実測と提出画像

AとBをそれぞれ**連続2周**実行し、2周目も同じ状態から開始できることを確認する。ログは課題番号/種類/予告/発射/スロー開始/実接触/解決/点/期限を実時間で記録。Bは受取/配膳、卓上着地/落下、箱の再受付も含める。画面上へデバッグ文字を常設しない。

最低限の提出画像：Aの帯成功、Aのケーキ飛散、Bの皿捕捉、Bの爆弾と穴、B弾群、B箱開封、A/Bの結果。動画を出せる環境なら各1周の記録を添付する。画像・動画を生成して動作実績を代用しない。

基準PC画面1920×1080で60fpsを目標にし、測定環境と実測を報告する。単にシーンをロードできたことを性能確認としない。XRでは実際の機器の更新周期に間に合うかを実機で後日測る。性能改善は描画統合、不可視物の処理削減、メッシュの共有、物理手法の改善で行い、対象数、演出の主構成、スロー時間、接触範囲を黙って削らない。

## 4. 納品内容と報告

ソース一式、依存バージョン、起動手順、A/B選択・VR/自動デモの切替手順、実行可能なビルド（環境で可能なもの）、AssetUsage、ライセンス、動作ログ、提出画像を残す。機密キーや個人の絶対パスを設定ファイルへ埋め込まない。

完了報告は「何が動いたか」「どの環境で見たか」「未確認事項」を分ける。PCデモの成功をVR初見体験の検証に読み替えない。

残る体験評価は、実機での手の届きやすさ、皿を受ける分かりやすさ、箱の離し方の納得感、爆弾が思いどおりにならない範囲、Bで意図的な早期失敗が得点上有利すぎないか。今回のCodexが独断でルール変更して解決する対象ではなく、観測を記録して次の仕様検討へ渡す。
