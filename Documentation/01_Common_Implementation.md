# 共通作成指示

## 1. 成果物と技術的裁量

既存の開発プロジェクトがあればその構成・互換バージョンを優先する。新規の場合の技術基準はUnity、OpenXR対応、PC単独実行可能な自動デモとする。Unityの正確なバージョン、描画パイプライン、XR/入力/GLB読み込み用パッケージは環境確認後に選び、理由と版をREADMEへ記録する。これは技術選択であって、別の2Dゲームや録画映像に置き換えてよいという意味ではない。

| Codexが決定してよい | この指示書で固定する |
| --- | --- |
| クラス構成、データ保持、シーン分割、オブジェクト再利用 | A/Bのルール、対象5種類、得点、順序、期限 |
| 互換パッケージ、インポート軸変換、レンダラー別の材質変換 | モデルと加工後の形、色、実寸、配置、見える動き |
| 衝突検出・サブステップ・補間の方式 | 見える接触が成功する範囲、再打撃の条件、スロー |
| 音声読込、フォントの静的変換、UI実装方式 | 音源、音量比、文字内容、字面の大きさ、UI座標 |
| バグ修正、描画のバッチ化、不可視物の処理削減 | VFXの方向・量・タイミング、デモ行動、カメラ演出 |

依存不足やバージョンの不一致は互換方法で解決し、逐一確認しない。仕様を維持できない場合だけ、該当箇所と実現可能な差分を報告する。新しいアイテムや説明画面、強打判定、吸着補助、難易度調整を追加しない。指定モデルの代用品を好みで選ばない。

対象機種の実機が接続されていなければ、PC完成・VR機能組込み・実機未確認を分けて報告する。Quest等の具体的な機種・ビルド先は引き継ぎ先の既存設定を確認して決める。現時点で特定機種の性能を保証しない。

## 2. 座標規約

- 1 unit = 1m。+X=プレイヤーの右、+Y=上、+Z=正面奥。
- `PlayerOrigin=(0,0,0)`は開始時の床上、頭の真下。基準の目線は`(0,1.65,0)`。
- 記載座標は右利き・基準身長の座標。位置は**指定した基準点**の値。寸法はX/Y/Zの実寸であり、Transform Scaleの値ではない。
- `center`は閉じた通常状態の外接箱中心、`bottom`は外接箱下面の中心。バットだけ`grip`を使用する。演出時の可動部は通常状態の寸法を基準とする。
- 正規化済みモデルの前面は-Z、上は+Y。箱の錠前、投球機の開口は前面。配布物を読み込む際の軸変換は技術的裁量だが、正規化後の向きは固定。
- 回転はdegree。曖昧さを避け、動くバットは「軸ベクトル」と「グリップ座標」、UIは「表面法線」、可動部は回転軸と角度で指定する。通常配置のyaw=0は正規化した正面が-Zを向く状態。
- 配置許容誤差はモデル寸法±2mm、固定オブジェクト位置±5mm。これは丸め・インポート誤差の上限であり、調整可能な幅ではない。

### 体格と左利き

開始時の立位の目線高Hを0.5秒平均で取得し、`dy=H-1.65`とする。床・遠景は動かさず、`body_height`指定の台天面、接触点、発射口、受取台、UIへ同じdyを加える。台の脚は床から新しい天面まで伸縮する。頭・手・XR Originを拡大縮小しない。モデル自体の大きさも変えない。座位を自動推測しない。

対応する初版の基準範囲は立位目線高1.35〜1.90m。範囲外は開始前の調整画面で「高さを合わせる」を出す。手動上下は1cm刻み、±20cm。自動デモはH=1.65固定。基準範囲が人のVR操作を検証済みという意味ではない。

左利きでは近接設備・接触点・飛来軌道・デモのXを反転する。配膳台と穴の左右も交換する。モデル前面/上向きと文字の向きは保持し、ルートに負のScaleをかけない。バットは選んだ片手で持つ。もう一方の手をバットへ接続する操作は要求しない。後景は共通のままでよいが、発射口の選択も鏡映する。

## 3. バットと手の外観

バットはこの寸法で専用メッシュを作る。細かな操作の成否を担うため、別の棒素材に合わせて寸法を変えない。回転体24分割、先端を丸めた金属バット。原点はグリップ中心、局所+Yが先端。

| グリップ原点からのY | 半径 | 色・用途 |
| --- | --- | --- |
| -0.12〜-0.10 | 0.030 | グリップエンド #344556 |
| -0.10〜0.12 | 0.016 | 握り #344556、溝6本・幅3mm |
| 0.12〜0.30 | 0.016→0.039 | 直線テーパー、#E7EEF0 |
| 0.30〜0.70 | 0.039 | 太い打撃部 |
| 0.70〜0.73 | 0.039→0.026 | 丸い先端、端面を閉じる |

全長0.85m。帯は局所Y=0.43〜0.68の0.25m。Aでは常時#F6C850、Bではボール時だけ同色、それ以外は#B7C4C8。模様も帯の両端の二重線で見えるようにする。帯が消えても当たり判定の太さは変わらない。

接触位置のバット中心線への投影Yが帯内なら20点、それ以外は10点。境界ちょうどは帯とする。バットの可視形状に沿った衝突体を使い、外見より大きい不可視の板にしない。移動途中の接触検出は連続的に行い、低い描画頻度ですり抜けないようにする。握りや先端へ当たった場合も通常の成功。手そのものは得点判定を持たない。

仮想の手は指を細かく動かさない白いミトン形。掌0.075×0.10×0.045m、親指は長さ0.05/半径0.018mの丸い形、手首リング直径0.065m。グリップ原点を握り、色は#F0ECE2、リング#344556。機器ごとのグリップ姿勢補正は持った見た目を合わせる技術調整。手の追従遅延や物理的な押し戻しで入力を加工しない。腕・胴体・足のモデルは表示しない。

### 照明・材質

主光の光線方向は正規化した(0.40,-0.85,0.35)、つまり上左前から、白#FFF5E6、床上の水平面照度1000luxを基準とする。影は一つ、軟らかい境界、色#657B83。環境光#B9CFDC、主光に対する明るさ0.35。露出は固定、画面の明暗に反応して変更しない。Kenneyのベースカラーを表示し、原則metallic=0/roughness=0.75。バット・弾・金貨のみmetallic=0.65/roughness=0.30。roughnessに相当する描画パラメータへの変換はCodexが行う。

ベイクやライト方式は変更可。見た目の基準は白い球に陰影が残り、背景が球より暗く、黒い爆弾の輪郭が背景へ溶けないこと。ブルーム、被写界深度、モーションブラー、色収差、ビネット、カメラシェイク、視野角変化、全画面白フラッシュはオフ。局所発光は描画上の明るい色と小さなハローで表現する。

## 5. UIと画面配置

日本語フォントは**Noto Sans JP**。数値は700、短い補助文は500。可変フォントを扱えない環境では同じ書体の静的フォントへ変換して使う。代替の日本語書体や英語だけへの置換はしない。入手元は06参照。

得点板の前面ローカル原点は中心、右が+X、上が+Y。以下の文字の「高さ」は見える字面の高さ。

| 要素 | 中心(X,Y)m | 表示枠幅/字高m | 内容 |
| --- | --- | --- | --- |
| 得点見出し | (-0.53,0.13) | 0.65/0.050 | 得点 |
| 得点数値 | (-0.53,-0.055) | 0.75/0.145 | 0〜99999 |
| 時間見出し | (0.53,0.13) | 0.65/0.050 | 残り |
| 時間数値 | (0.53,-0.055) | 0.75/0.145 | 90〜0、整数切り上げ |
| 最後の課題 | (0.53,-0.055) | 0.78/0.085 | 最後の1つ |

板#294551、文字#F7F4E9、中央仕切り幅0.006m。背景枠にUI Packの`button_rectangle_flat.png`を9-sliceで用い、テクスチャ色をこの色へ統一する。板外周角丸半径0.035m。上辺の開始ランプはx=-0.16,0,0.16、y=0.30、半径0.04m。1秒に一つ消し、3秒後に本番を開始。

メニューは開始時だけ`center=(0,1.38,1.8)`、前面-Z、幅1.2/高0.70m。上段タイトル字高0.075m、中段「右手」「左手」ボタン各0.30×0.12m、下段「体験する」「開始」各0.40×0.14m。選択した利き手にチェックマーク。PCでは別の小さな列に「A」「B」「自動デモ」を置く。メニューは遊びの間は消す。

導入中の「開始」は主対象にかからない`(0.9,1.80,1.8)`、0.35×0.14m、字高0.055m。VRでは空いている手の短いポインター+決定ボタン、PCではクリックで選ぶ。遊びの最中にポインターを表示しない。利き手ボタン・メニューの文字を左利きでも左右反転しない。

加点は対象中心+`(0,0.20,0.06)`に字高0.075m、0.45秒。上へ0.12m移動、最後0.15秒で消える。銃弾群は一つの合計表示へ集約する。説明文、照準、速度計、コンボ表示は置かない。

結果板は`(0,1.75,2.1)`、幅1.5/高0.80m。上からタイトル、総得点、Aは「打てた数／帯の数」、Bは5種類の成功数。中央の得点字高0.14m、他0.065m。Bの銃弾は「弾：命中数／飛来数」と「全弾：完遂群数／提示群数」の2行。他は成功課題数/提示課題数を表示する。Bの種類別結果は横に5列、各列幅0.27m/列中心X=-0.56,-0.28,0,0.28,0.56、見出しY=-0.08、数値Y=-0.18、弾群追加行Y=-0.255。種類別の字高は0.045m。A/B切替と再挑戦は結果の最下段。自動デモは6秒後に同じ案を最初から再開する。

PC画面は16:9、基準1920×1080、垂直FOV=70°。他比率は同じ垂直FOVを維持、HUDの端からの余白32px以上。PCの「自動デモ」は左上(32,28)px、字高26px、白字、半透明濃紺0.7の帯。VRのFOVは機器へ任せ、強制変更しない。

## 6. 進行・時間・入力に関する禁止事項

全体90秒と個別期限は実時間で進む。例外は入力追跡喪失/明示的一時停止と、Bの到達不能バグからの復帰時のみ。Bの復帰時は全体時計を進めたまま、残り0.8秒未満の場合だけ爆弾時計を最大0.45秒止め、復帰後0.35秒を確保する（今回の指示書で確定した異常復帰規則）。通常の静止や苦戦に適用しない。スローは指定対象の移動を0.2倍にする処理であり、HMD、手、UI、時計へ影響させない。全体TimeScale変更だけで実現しない。ゲームの物理処理方法が異なっても同じ時間関係を守る。

同時に操作する課題は一つ。解決後0.60秒を空けて次の0.80秒予告を開始する。B爆弾の期限切れだけ片付け1.00秒を使い、0.60秒を重ねて足さない。90秒時点で未発射の予告は中止、発射済みの一課題は固有の期限まで完遂する。

速度・加速度・力・角速度から成否、得点、打球距離、演出の強さを求めない。置いたバットへの接触を成功とする。接触検出精度のために速度を参照することと、速度をプレイ評価に使うことは区別する。
